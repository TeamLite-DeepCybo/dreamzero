# Eval dashboard

A static web dashboard for inspecting open-loop eval runs of our DreamZero
checkpoints: per-sample horizon-24 MSE vs the hold-position baseline, MSE(t)
divergence charts, a 3D robot replay of predicted vs ground-truth actions
(three.js + urdf-loader), camera-frame context, and dreamed-video overlays
for runs evaluated with `--dump_dream_dir`.

No build step and no backend: plain HTML/JS served statically, with three.js
and urdf-loader loaded from CDN import maps (needs internet access in the
browser).

## Running it

```bash
cd dashboard

# 1. One-time: fetch the robot model (URDF + meshes, kept out of git)
./setup_robot.sh

# 2. Python env for the data builder
python3 -m venv .venv && .venv/bin/pip install numpy

# 3. Pull eval results and build the dashboard JSON
#    (requires SSH access to the storage machine, see below;
#     export DASH_REMOTE=<user>@192.168.100.124 first)
./refresh.sh

# 4. Serve
python3 -m http.server 8123
# open http://localhost:8123
```

## Data flow

Every eval run of `scripts/open_loop_deepcybo.py` (or the b300-convention
variant) writes a `chunks.npz` — arrays `pred`, `gt`, `hold` of shape
(N, 24, 16) plus `idx` — into its `--output_dir`. Runs we want to keep are
copied to the storage machine (`192.168.100.124`, an
A6000 box used for long-term artifacts) under
`~/dreamzero_eval/results/<run_name>_dense/chunks.npz`.

- `refresh.sh` pulls every `results/*_dense/chunks.npz` from that machine
  into `data/<run>.npz` and then runs the builder.
- `build_data.py` converts the npz files into `data/samples.json` (shared
  ground truth + per-sample metadata) and `data/runs.json` (per-run
  predictions and metrics). **All runs are scored against the ground truth
  of the alphabetically first npz**, so every npz must use the same sample
  grid and the same joint order.
- `data/profiles.json` configures the UI: robot model, data sources, camera
  calibration, and the mapping from run name to a dreamed-frames directory
  (`dream_seq_*`, JPEGs named `idx<IDX>_t<T>.jpg` as written by
  `--dump_dream_dir`).

### Joint-order warning

The dashboard and all `v3_*` runs use the state/action layout
`[left 7 joints, right 7 joints, left gripper, right gripper]`.
Checkpoints evaluated through `open_loop_b300native.py` produce chunks in
the B300 dataset layout `[L7, LG, R7, RG]`; permute them with
`np.argsort(REORDER)` (where
`REORDER = list(range(0,7)) + [14] + list(range(7,14)) + [15]`) before
placing them in `data/`, or both the metrics and the 3D replay will be
computed against scrambled channels.

## Files

| file | purpose |
|---|---|
| `index.html` / `app.js` | the whole UI |
| `build_data.py` | npz → dashboard JSON |
| `refresh.sh` | sync results from the storage machine + rebuild |
| `setup_robot.sh` | fetch URDF + meshes from `TeamLite-DeepCybo/lite_urdf` |
| `data/profiles.json` | UI configuration (profiles, calibration, dream dirs) |
| `data/dashboard_data/samples_meta.json` | per-sample episode/prompt/frame metadata |
| `CAMERA_EXTRINSICS_FINDINGS.md` | notes on the camera-overlay calibration (the head camera is a 147° fisheye; the pinhole overlay only matches near image center) |

Bulk artifacts (npz files, dreamed frames, robot meshes, camera frame dumps)
are intentionally not in git — see `.gitignore`. They are regenerated by the
scripts above or pulled from the storage machine.
